# AI 사용 기록

허용 범위는 개념 질문과 자신이 작성한 코드의 디버깅입니다. 과제 함수의 정답이나 전체 구현을 대신 생성하게 해서는 안 됩니다. 먼저 현재 단계 검사를 실행하세요.

사용하지 않았다면 아래에 사용하지 않았다고 적습니다. 사용했다면 질문마다 기록합니다. API 키, 개인 이메일, 실제 회사 데이터는 입력하지 않습니다.

## 사용 여부와 범위

- 사용 여부: 사용함.
- 도구와 모델 이름: OpenAI Codex 데스크톱 앱의 대화형 AI 어시스턴트(GPT-6 기반). 정확한 세부 모델 식별자는 확인하지 못했다.
- 기록 범위: LangChain 과제의 필수 1~5와 선택 심화. 반복 질문은 주제별로 묶고, 질문의 말투·맞춤법을 정리했다. 아래 질문은 원문 그대로의 인용이 아니다.
- 받은 도움: 개념·별도 예시, 작성한 코드의 검토와 수정 힌트, 인자·키 이름·조건·반환문 등 짧은 코드 예시, 이유 주석의 수정 표현, 실행 순서와 결과 해석. 선택 심화에서는 입력 파악부터 검토·수정·재검토의 순서와 분기별 반환 구조까지 단계별 안내를 받았다.
- 직접 작업과 파일 수정 구분: main.py의 구현을 직접 입력·수정하고 명령을 실행했다. AI는 프로젝트 안내·코드·저장 결과를 읽었으며 이 대화에서 main.py, support.py, checks.py와 제공 자료를 직접 편집하지 않았다. 이 AI_USAGE.md는 요청에 따라 AI가 대화와 로컬 결과를 대조해 작성했다. 개념 설명만 받은 것으로 축소하지 않고 수정 예시와 심화 흐름에 관한 도움도 포함했다.
- 과제 프로그램의 실제 모델 호출과 코딩 도움을 받은 대화 모델은 별개다. README의 기본 호출 모델은 gpt-5.6-luna이지만, 현재 결과 JSON에는 모델명이 표시되지 않아 기본값을 실제 사용 모델로 단정하지 않았다.

## AI의 설명이 틀렸거나 그대로 적용하지 않은 부분

- 입력 보존을 재현성이나 로그 저장으로 이해했으나, 설명과 실제 호출 코드를 대조해 현재 요청의 질문·이력을 다음 단계에 전달하는 역할로 바로잡았다.
- 키워드 합산은 AI가 대괄호를 생략한 형태도 제안했으나 직접 작성한 리스트 형태를 유지했다. HumanMessage도 content 키워드가 명확하다는 설명을 받았지만 동작하는 위치 인자 형태를 유지했다.
- 오류 이름 조건은 AI가 error is not None을 권했으나 현재 코드는 if error를 유지했다. 기본 예외로 검사를 통과했다는 사실과, 모든 예외 객체의 참/거짓 동작을 보장하는 것은 구분한다.
- 실제 기본 체인의 category=general을 형식 오류로 보지는 않았지만, 개발환경 문의에는 installation이 더 적절하다는 의미 검토 설명을 받았다. 실제 실행에서 관찰한 분류를 임의로 통과 결과처럼 바꾸지 않았다. POLICY_SOURCE는 B1을 유지했다.
- AI가 앞서 필수 기능 완료를 안내했어도 제출 문서와 주석까지 자동 완성됐다는 뜻으로 보지 않았다. 현재 stream_answer의 관측 메모는 안내 주석만 남아 있어 제출 전 직접 작성해야 한다.

## 확인한 실행 결과와 한계

- 저장된 필수 전체 검사: 56개 통과, 0개 실패. 세부는 검색 7, 기본 체인 13, 대화 이력 4, 실패 복구 13, 스트리밍 19이다. 선택 심화는 별도 6개 통과, 0개 실패이다.
- 실제 기본 체인: Python 3.12, policy-python, needs_human=false, route=primary를 확인했다. category는 general이어서 내용상 적절한 분류와 차이가 있었다.
- 실제 대화 이력: A 두 턴·B 한 턴이 모두 primary였다. A의 후속 질문에 3.12로 답했고 A 4개·B 2개 메시지를 확인했다. 이 소수 사례만으로 모든 세션 격리 상황을 보장하지 않는다.
- 실제 스트리밍: model_attempts=1이고 청크 전달 후 최종 Python 3.12 안내, policy-python 출처, installation 분류와 primary 경로를 확인했다.
- 중간 실패 관찰은 외부 장애를 일으킨 것이 아니라 fixture 시나리오였다. 대화에서 확인한 delta 1개→reset(unverified_output)→final fallback 결과와, 실제 모델의 정상 스트리밍 결과를 구분했다.
- 심화의 3.11→3.12 수정 및 검토/수정 횟수는 제공된 고정 함수의 제어 흐름 검증이다. 실제 모델의 자체 검토 성능이나 일반적인 답변 품질 측정으로 주장하지 않는다.
- 이 기록을 정리하면서 저장된 결과 파일을 읽었으며 검사나 실제 모델을 새로 호출하지 않았다. 기록만 갱신했고 구현·제공 자료는 변경하지 않았다.

## 최종 코드와 설명을 스스로 설명할 수 있는지 확인

직접 설명할 핵심: 입력 보존과 검색 결과 병합, 객체와 딕셔너리 키 및 함수 인자의 차이, 파서와 출처 검증, 근거와 대화 이력의 구분, 재시도 상한, delta/reset/final, 경과 시간·오류·청크 기록, 심화의 수정 1회 및 재검토 경로이다. 전체 이해 여부는 AI가 대신 확정하지 않으며 제출 전에 직접 점검한다.

키·개인정보는 이 기록에 포함하지 않았다. stream_answer의 관측 메모를 실제 실행에 근거한 문장으로 작성하는 확인은 남아 있다.
