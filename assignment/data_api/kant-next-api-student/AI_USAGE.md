# AI 사용 기록

AI는 개념 질문과 직접 작성한 코드의 디버깅에만 사용할 수 있습니다. 사용하지 않았다면 아래에 `사용하지 않음`이라고 적습니다. 사용량을 늘릴 필요는 없습니다.

| 허용되는 도움 | 예시 |
|---|---|
| 개념 이해 | HTTP 404와 422의 차이, await의 의미를 다른 예시로 설명해 달라고 질문 |
| 자신의 코드 디버깅 | 직접 작성한 짧은 함수와 오류를 보여 주고 원인과 확인 방법을 질문 |

과제 전체 풀이, TODO의 완성 코드, 참고 답안을 요청하지 않습니다. 디버깅 답변도 이해한 원인과 수정 내용을 자신의 말로 기록하고 다시 실행합니다. API 키, `.env`와 인증 헤더를 질문에 포함하지 않습니다.

## 사용 여부

- 사용 여부: 사용함
- 사용한 도구: OpenAI Codex 데스크톱 앱. 대화에 사용된 정확한 세부 모델 식별자는 확인하지 못함.
- 사용 기간: 2026-10-23~2026-10-29.
- 활용 내용: 개념·별도 예시, 작성한 코드의 검토와 오류 원인·수정 위치·연산자·호출 형태, 실행 순서와 결과 해석을 안내받았다. 선택 심화에서도 문서 검색·상태 판단·변경 기록·정렬에 관한 단계별 힌트를 받았다.
- 작성 구분: 구현 코드는 사용자가 직접 작성·수정·실행했다. AI는 코드를 읽고 일부 함수 검사를 수행했으며, 이 대화에서 app.py나 제공 자료·검사 코드를 직접 편집하지 않았다. 이 기록은 AI가 대화와 저장 결과를 확인해 정리했다.
- 표의 질문은 표현을 정리한 요약이며, 같은 주제의 반복 질문은 묶었다. 과제에서 실제 호출한 `gpt-5.6-luna`는 코딩 도움을 받은 대화 도구의 모델과 구분한다.

## 도움 기록

| 단계/함수 | 직접 시도한 내용과 문제 | 질문 요약 | 받은 설명 | 내가 수정하거나 확인한 내용 | 재실행 결과 |
|---|---|---|---|---|---|
| 수집 / `collect_releases` | 요청 파라미터·응답 상태·다음 페이지 조건과 저장 코드를 작성했다. json.dump의 위치 인자 오류와 미저장 코드 실행이 있었다. | 요청 조건과 response.links는 무엇이며, 어떤 값을 파일에 저장하나요? | params는 딕셔너리로 전달하고 응답 메서드로 상태를 검사한다. next 키로 다음 페이지를 판단하며, 저장할 데이터와 열린 파일을 구분한다. | page·per_page, 상태 검사, 다음 페이지 조건과 value 저장을 작성·수정했다. 파일 저장 후 다시 실행했다. | `check collect` 9개 통과. fixture 수집 2페이지·10건 확인. |
| 정제 / `normalize_releases` | 플래그 자료형, 제목 대체, 빈 본문과 채택 ID 중복을 검사하는 조건을 작성했다. None과 빈 문자열 및 검사 대상 변수를 잘못 사용한 부분이 있었다. | 자료형·누락·공백 검사와 제목 대체 조건을 어떻게 구분하나요? | 값과 자료형 검사는 다르다. get과 None 선검사로 누락을 처리하고, 정리한 본문·URL·수집시각을 문서에 연결한다. | boolean 검사, 이름·태그 선택, 빈 본문·중복 ID 조건, 문서 필드 값을 수정했다. | `check documents` 22개 통과. fixture는 채택 3·격리 5·제외 2건. |
| 모델 / `Document`, `QueryRequest`, `QueryReply` | 필드의 타입·길이·기본값을 선언했다. 목록 타입과 실제 값, Literal 사용 위치를 확인했고 필드가 검증 함수 안에 들어간 오류가 있었다. | 모델 필드는 어떤 형식과 위치에 선언하나요? | Field·Literal·목록 원소 타입과 필수/기본값을 구분한다. 필드는 클래스에 선언하고 작성 후 미구현 표시를 정리한다. | 문서 6필드·질문 3필드·답변 4필드를 작성하고, 키 오타·타입·기본값·들여쓰기를 수정했다. | 답변 모델·OpenAPI 오류 수정 후 `check document-api` 7개 통과. |
| 문서 API / `response_models`, `find_document`, `register_document` | 요청·응답 모델을 연결하고 조회·중복 조건을 작성했다. 객체의 속성과 딕셔너리 조회를 혼용했고 수동 시험에서 JSON 문법 오류가 있었다. | 없는 문서와 중복 등록을 어떻게 검사하며, 422는 무엇을 뜻하나요? | 응답 모델과 저장소 키 검사, Document의 URL 속성 비교를 설명받았다. JSON 해석 오류와 필드 검증 오류를 구분했다. | 모델 연결과 ID·URL 조건을 수정했다. `/docs`에서 조회·등록·중복·빈 제목을 직접 시험했다. | 정상 조회 200, 없는 ID 404, 등록 201, 중복 409, 빈 title의 string_too_short 422 확인. |
| 모델 연결 / `build_prompt`, `call_model_once` | 입력을 JSON으로 묶고 답변·출처를 검증했다. dumps 인자, 응답 전체와 추출 text, 출처 조건의 방향에 오류가 있었다. | 질문과 문서를 어떻게 전달하고 답변을 어떤 순서로 검증하나요? | 입력은 지정된 키의 딕셔너리로 묶는다. 추출 text를 loads로 읽은 뒤 모델 검증하고, 선택하지 않은 출처가 있는지 검사한다. | question·selected 연결, JSON 해석·모델 검증 호출, any/not in 조건을 수정했다. | `check query` 6개 통과. 실제 모델 1회 호출 답변은 policy-python 문서와 대조했다. |

| 제한·로그 / `admit_query`, `request_logging` | 시간 구간·횟수 조건과 로그 필드를 작성했다. window와 limit, and/or 및 비교 방향에 오류가 있었다. | 구간 갱신·한도 판단과 기록할 값은 어떻게 구분하나요? | 첫 요청/구간 경과와 count 한도를 별도로 검사한다. | 심화 / `compare_snapshots` | 두 목록의 ID 비교·검색, 상태·변경 필드 기록, 결과 누적과 정렬을 직접 작성했다. 위치별 비교, any의 반환값, 실제 값과 타입, added 조건, 반환·빈 함수 선언에 오류가 있었다. | 같은 ID의 문서를 찾고 네 상태와 변경 필드를 어떻게 구분하나요? | 목록과 개별 문서, 존재 여부와 문서 검색을 구분했다. next·sort/key/lambda의 별도 예시와 상태 판단·문서별 초기화·실제 값 기록에 관한 단계별 설명을 받았다. | 작성한 반복·검색·조건·결과 딕셔너리·정렬을 수정했다. 원본을 보존하고 수집시각만의 차이를 제외했다. 본문 없는 함수 선언도 정리했다. | AI의 함수 분리 검사 2개 후 직접 `check challenge` 3개 통과. 빈 입력·순서 변경·여러 변경·원본 보존·API 연결 확인. |

## 최종 확인

- **고정 검사:** 저장된 최종 결과에서 필수 `check all` 67개, 선택 심화 `check challenge` 3개가 모두 통과했다. 기록 재작성 중 검사를 새로 실행한 것은 아니다.
- **실제 수집·정제:** GitHub 2페이지·10건 수집에 성공했다. limited=true이므로 전체 릴리스 이력 수집은 아니다. 실제 자료 정제는 10건 채택, 격리·제외 각 0건이었다.
- **실제 모델:** `run query --live`의 1회 호출에서 policy-python을 선택했다. Python 3.12와 환경 구성 명령·주의사항이 문서와 일치했고, 출처는 policy-python, needs_human은 false, category는 installation이었다.
- **심화 결과:** policy-incident는 added, policy-python은 unchanged, policy-secret은 missing, policy-uv는 changed(body)로 반환되었다. ID순 정렬을 확인했으며 missing을 실제 삭제로 단정하지 않았다.
- **검증 범위:** 재시도·요청 제한·동시성은 fixture 검사 범위다. 실제 공급자 장애나 운영 부하 시험은 수행하지 않았다. 전체 서버의 실제 모델 `/query` 수동 응답은 이 대화에서 별도 확인하지 않았으므로, 단일 실제 모델 호출과 fixture API 검사를 구분했다.
